What is this, really?

A whole studio inside your AI assistant

Forget the technical words for a minute. Here's the simple version, no programming background needed.

👩‍💻

The coder

Writes the actual code, step by step. Never dumps a giant change all at once.

🔍

The reviewer

Reads every change before it ships. Blocks anything that looks risky or sloppy.

🧪

The QA tester

Keeps a list of things that should work. Flips items to FAIL when something breaks.

🛠️

The bug fixer

Investigates failures, finds the real cause, fixes it, and adds a regression test.

📋

The analyst

Turns your idea into a clear specification — what should happen, what shouldn't.

🎨

The designer

Plans how the screen looks and what the user does — for visual features.

That's ai-agent-kit. It installs this team of 10+ AI agents into your project — along with the rules, workflows, and quality checks they need so they don't drift off-task, forget context, or quietly write fragile code. You stay in charge. They handle the engineering legwork.

Это и есть ai-agent-kit. Он устанавливает в ваш проект команду из 10+ ИИ-агентов — вместе с правилами работы, процессами и контролем качества, чтобы они не теряли контекст, не забывали детали и не писали хрупкий код потихоньку. Главным остаётесь вы. Они берут на себя инженерную рутину.
Why a team, not just one AI?

Five problems a coordinated team fixes

One AI assistant is great for quick tasks. But shipping anything serious means specs, reviews, tests, fixes, and continuity. Here's what changes when you have a coordinated team instead of a single chat.

I have an idea but I don't write code
Describe what you want in plain English. The analyst turns it into a spec, the coder builds it, the reviewer audits, the QA tester verifies. You stay the product owner — they handle the engineering.
My AI keeps losing context
A single chat forgets older decisions and contradicts itself. A team passes structured artifacts — requirements, spec, test cases — between agents, so context survives even if your chat restarts.
No one reviews the AI's code
Solo AI coding goes uninspected. Here, every change runs through a read-only reviewer before it ships. Issues block progress; the coder fixes them; the cycle repeats. No big-bang merges.
Bugs surface later, not now
A markdown file lists every test case with its status — pass, fail, pending. Mark something as fail, run one command, and the team triages, fixes, and re-verifies it without you babysitting.
I want process, not chaos
Each command runs a defined pipeline with quality gates. You always know who's doing what, where the work is, and what's blocking it — instead of a wall of AI output you have to make sense of.
I'm scared the AI will quietly break things
Every change is a normal git commit. The reviewer reads it first. The QA list catches regressions. If something still slips through, you can revert to any earlier point in seconds.
Зачем команда, а не один ИИ?

Шесть проблем, которые решает команда

Один ИИ-ассистент хорош для быстрых задач. Но чтобы сделать что-то серьёзное, нужны ТЗ, ревью, тесты, исправления и преемственность. Вот что меняется, когда у вас слаженная команда вместо одного чата.

У меня есть идея, но я не программист
Опишите что хотите обычными словами. Аналитик превратит идею в ТЗ, программист соберёт код, ревьюер проверит, тестировщик удостоверится, что всё работает. Вы остаётесь владельцем продукта — они занимаются инженерией.
ИИ постоянно теряет контекст
Обычный чат забывает старые решения и противоречит сам себе. Команда передаёт между агентами структурированные артефакты — требования, ТЗ, тест-кейсы — и контекст не пропадает, даже если чат перезапустился.
Никто не проверяет код за ИИ
Когда ИИ кодит в одиночку, его никто не контролирует. Здесь каждое изменение проходит через ревьюера в режиме только-чтения. Найдены проблемы — программист чинит, цикл повторяется. Никаких больших мерджей одним куском.
Баги всплывают потом, а не сейчас
Markdown-файл со списком всех тест-кейсов и их статусами — pass, fail, pending. Помечаете что-то как fail, запускаете одну команду — команда сама разберётся, починит и перепроверит. Без вашего ручного контроля.
Хочется системности, а не хаоса
Каждая команда запускает определённый пайплайн с проверками качества. Вы всегда знаете, кто что делает, где работа и что её блокирует — вместо стены ИИ-вывода, в которой нужно разбираться.
Боюсь, что ИИ потихоньку всё сломает
Любое изменение — это обычный git-коммит. Ревьюер читает его первым. Список QA ловит регрессии. Если что-то всё-таки проскочило — за секунды откатываетесь к любой более ранней точке.

Profile architecture

Build your setup from profiles

A profile is one building block of your kit setup — like ticking one checkbox on an order form. Each profile says one thing: "I'm using Kotlin," "I'm building a Compose app," "Run on Claude Code," "Add security rules."

kotlin-gradle + compose-multiplatform + claude-code + security-baseline = your project setup

You pick a few when you install — the kit assembles them into your project. Want SOLID design principles later? Add the solid profile; language, framework, and host stay untouched. Switching from Claude Code to OpenCode? Replace just the host profile.

The five categories of profiles

Every profile belongs to one of these five categories (technically called axes). Each category answers a different question about your project, so profiles never overlap or conflict.

Specific profile names look technical, but you don't need to memorise them. The install prompt asks plain questions ("What language?", "Which AI assistant?") and picks the right profiles for you.
Архитектура профилей

Соберите свою конфигурацию из профилей

Профиль — это один кирпичик настройки кита, как одна галочка на бланке заказа. Каждый профиль говорит одну вещь: «у меня Kotlin», «я делаю приложение на Compose», «работаю в Claude Code», «добавь правила безопасности».

kotlin-gradle + compose-multiplatform + claude-code + security-baseline = конфигурация вашего проекта

На установке вы выбираете несколько штук — кит их собирает в проект. Захотелось добавить принципы SOLID позже? Добавьте профиль solid — язык, фреймворк и хост не тронутся. Переходите с Claude Code на OpenCode? Замените только профиль хоста.

Пять категорий профилей

Каждый профиль принадлежит одной из пяти категорий (технически они называются осями). Каждая категория отвечает на свой вопрос о вашем проекте, поэтому профили никогда не пересекаются и не конфликтуют.

FAQ

Common questions

If you've never used an AI agent kit before, these are probably the questions on your mind.

Do I need to know how to code?

Not really, but it helps. The kit handles the engineering side — coding, reviews, tests. You need to be able to:

• describe what you want clearly,
• run commands in a terminal,
• check whether the result matches your idea.

If you've ever written a careful brief for a freelancer, you have the skill.

How much does this cost?

The kit itself is free and open source. The cost is the AI assistant you use it with — typically Claude Code, OpenCode, or Cursor — plus the underlying model API calls.

Expect a few dollars per significant feature, depending on how much code is involved. There are no kit-specific fees.

What if the AI makes a mistake?

The whole point of the team setup is that one agent's mistakes are caught by another. The reviewer reads every change before it ships. The QA agent maintains a list of test cases that flip to FAIL when something breaks.

And every change is just a normal git commit — you can always revert to any earlier point.

Where does my code live? Is it private?

On your machine, in your project's git repository. Same as if you wrote it yourself.

The kit doesn't upload code anywhere. The AI assistant you've chosen sends snippets to its provider while you're working — that's the same trade-off as using any AI coding tool.

Is this safe to use on real projects?

Yes, with normal precautions:

• never paste API keys into the manifest (the install prompt rejects them automatically),
• commit your work to git regularly,
• review meaningful changes before merging.

The same rules as working with any AI coding assistant — the team setup just makes the safety net wider, not weaker.

Which AI assistant should I pick — Claude Code or OpenCode?

Claude Code — easiest setup, best Claude models, polished experience.

OpenCode — flexibility: pluggable model providers, more open architecture.

You can also install both side-by-side and switch between them. The agent team is identical on both.

What if I get stuck mid-pipeline?

Run /kit-status — it tells you which stage is active, what's blocking it, and what's next. Run /kit-resume to continue exactly where you left off, even after closing your AI assistant.

For a long pipeline, run /kit-checkpoint at known-good moments so you can rewind to them safely.

Can I customise an agent's behaviour?

Yes. Each agent is just a markdown file in .claude/agents/ or .opencode/agents/. Open it, edit the prompt, save. The next run uses the new instructions.

For deeper changes — add or modify capability profiles, then run /kit-update to re-render everything cleanly.

FAQ

Частые вопросы

Если вы раньше не работали с китом ИИ-агентов, скорее всего, у вас в голове крутятся именно эти вопросы.

Нужно ли уметь программировать?

Не обязательно, но полезно. Кит сам занимается инженерной частью — кодом, ревью, тестами. От вас требуется уметь:

• чётко описать, чего вы хотите,
• запускать команды в терминале,
• проверять, соответствует ли результат вашей задумке.

Если вы когда-нибудь писали внятное ТЗ фрилансеру — у вас уже есть нужные навыки.

Сколько это стоит?

Сам кит бесплатный и с открытым кодом. Платите вы за ИИ-ассистент, который его запускает — обычно это Claude Code, OpenCode или Cursor — плюс за вызовы API моделей.

На серьёзную фичу обычно уходит несколько долларов, в зависимости от объёма кода. Дополнительных платежей именно за кит нет.

А что, если ИИ ошибётся?

Смысл командной настройки в том, что ошибки одного агента ловит другой. Ревьюер читает каждое изменение перед тем, как оно попадёт в код. QA-агент ведёт список тест-кейсов, которые переключаются в FAIL, когда что-то ломается.

А любое изменение — это обычный git-коммит. Всегда можно откатиться к любой более ранней точке.

Где хранится мой код? Это приватно?

На вашем компьютере, в вашем git-репозитории. Точно так же, как если бы вы писали его сами.

Кит ничего никуда не загружает. ИИ-ассистент, который вы выбрали, отправляет фрагменты кода своему провайдеру во время работы с ним — это тот же трейдофф, что и при использовании любого ИИ-кодера.

Можно ли использовать на реальных проектах?

Да, с обычными мерами осторожности:

• не вставляйте API-ключи в манифест (установочный промпт сам это отбрасывает),
• регулярно коммитьте работу в git,
• просматривайте значимые изменения перед мерджем.

Правила те же, что и при работе с любым ИИ-кодером — командная настройка просто делает страховочную сетку шире, а не уже.

Какой ИИ-ассистент выбрать — Claude Code или OpenCode?

Claude Code — самая простая установка, лучшие модели Claude, отполированный UX.

OpenCode — гибкость: подключаемые провайдеры моделей, более открытая архитектура.

Можно установить оба параллельно и переключаться. Команда агентов в обоих одинаковая.

А если я застряну посреди пайплайна?

Запустите /kit-status — он покажет, какой этап сейчас активен, что его блокирует и что дальше. /kit-resume продолжает ровно с того места, где остановились — даже после закрытия ИИ-ассистента.

На длинных пайплайнах используйте /kit-checkpoint в известно-рабочих точках, чтобы безопасно к ним откатываться.

Можно ли поменять поведение агента под себя?

Да. Каждый агент — это просто markdown-файл в .claude/agents/ или .opencode/agents/. Открываете, редактируете промпт, сохраняете. Следующий запуск использует новые инструкции.

Для более глубоких изменений — добавьте или модифицируйте capability-профили, затем запустите /kit-update для чистой перегенерации.
